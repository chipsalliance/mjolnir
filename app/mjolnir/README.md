# Mjolnir Application Engine

This directory contains the core Python application engine for Mjolnir. It handles the orchestration of the security analysis, interacting with AI models, and generating reports/dashboards.

## Directory Structure

- `main.py`: The entry point of the application engine. It parses the job spec, sets up the repository, runs the analysis, and generates the output.
- `agent_tools/`: Python tools that the AI agents can use to inspect the codebase (e.g., `read_file`, `grep_search`, `glob`).
- `data/`: Pydantic data models defining the schema for vulnerabilities, findings, verdicts, and status.
- `providers/`: Execution engines.
  - `adk/`: The core production analysis engine built on Google's Agent Development Kit.
  - `mock/`: Internal mock engine that returns pre-defined findings, used for fast deterministic pipeline tests.
- `utilities/`: Helper modules for logging, dashboard generation, git operations, GCS upload, and metadata tracking.

## Execution Flow

1.  `main.py` is called with a path to a JSON job specification (usually generated by Nix).
2.  It clones/updates the target repository and checks out the specified revision.
3.  It discovers source files to scan based on job configuration.
4.  It executes the analysis based on the configured `model` (e.g. `mock` engine for `model = "mock"`, or `adk` engine for foundation models):
    - **Phase 1 (Audit)**: Scans source files to identify potential vulnerabilities.
    - **Phase 2 (Review)**: Uses an adversarial reviewer agent to filter out false positives.
5.  It writes the findings to `vulnerabilities.json` and a filtered version to `vulnerabilities_minimal.json` in the run directory.
6.  It records telemetry report files (`token_usage.json` and `tool_usage.json`) in the run directory so CI data is never lost.
7.  Optionally uploads results to Google Cloud Storage.

## Analysis Execution

Mjolnir's vulnerability analysis is powered natively by Google's Agent Development Kit (ADK) under `providers/adk/`:

- **ADK Engine (`providers/adk/`)**: The core production analysis pipeline. It executes multi-phase agent workflows (`Phase 1: Audit` file scanning and `Phase 2: Review` adversarial triage) with tool calling, context caching, and structured findings.
- **Mock Simulation (`providers/mock/`)**: A fast, deterministic mock engine used exclusively during CI tests and local smoke testing (`model = "mock"`). It produces static findings without making LLM calls or consuming tokens.

## Logging & Observability

Mjolnir uses a dual-destination logging architecture configured in `utilities/logger.py`:

- **Console Output**:
  - `sys.stdout`: Receives `INFO` level events (standard progress updates, `logger.header(...)` gold stage titles, `logger.success(...)` green completion notices).
  - `sys.stderr`: Receives `WARNING`, `ERROR`, and `CRITICAL` log events.
- **Run Log File (`<run_dir>/job.log`)**:
  - Captures `DEBUG` level and above with ISO timestamps (`%(asctime)s [%(levelname)s]`).
  - Includes detailed tool call execution logs, low-level traces, and full exception stack traces for deep troubleshooting.
